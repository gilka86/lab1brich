## Запуск
Необходимы Node.js указанной версии и npm.
Из корня скачанного проекта выполните:
```bash
cd frontend
npm ci
npm run dev
```

Откройте в браузере адрес, который напечатает терминал.
Для остановки сервера нажмите Ctrl+C.

## Проверка типов и сборка
Находясь в папке frontend, выполните:
```bash
npm run build
```
Команда сначала проверяет TypeScript, затем создаёт сборку в frontend/dist.
Для просмотра готовой сборки:
```bash
npm run preview
```
Откройте адрес из терминала. Для остановки нажмите Ctrl+C.

## Что работает сейчас

- Регистрация и вход по email и паролю через Supabase Auth.
- Подтверждение email согласно настройкам Supabase.
- Восстановление сессии после обновления страницы.
- Выход из аккаунта.
- Защита личных страниц через RequireAuth.
- Создание, просмотр, редактирование и удаление заметок.
- Постоянное хранение заметок в Supabase PostgreSQL.
- Фильтрация заметок по статусу.
- Загрузка категорий из Supabase.
- Обработка ошибок загрузки и сохранения.
- Разделение заметок между пользователями через RLS.

## Лабораторная работа №5. Схема данных и справочник в Supabase

Справочник категорий хранится в Supabase (PostgreSQL) и читается формой через supabase-js.
Основные заметки по-прежнему хранятся в состоянии App и после перезагрузки возвращаются к демонстрационному набору. Постоянным стал только справочник.

Переменные окружения (значения в .env.local, в Git не попадают):
- VITE_SUPABASE_URL
- VITE_SUPABASE_PUBLISHABLE_KEY

Шаблон: frontend/.env.example. SQL: supabase/migrations и supabase/seed.sql.

## Лабораторная работа №6
### Авторизация и сохранение личных записей

В приложении реализована авторизация пользователей
через Supabase Auth по email и паролю.

### Авторизация

- Создан хук useAuth для отслеживания состояния сессии.
- Реализованы регистрация и вход через AuthPage.
- Добавлено восстановление сессии после перезагрузки.
- Создан RequireAuth для защиты личных маршрутов.
- Добавлена кнопка выхода из аккаунта.
- Во время проверки сессии личные страницы не показываются.

### Постоянное хранение заметок

Создан сервис frontend/src/services/notes.ts.

Реализованы операции:
- getNotes — получение заметок;
- createNote — создание заметки;
- updateNote — редактирование заметки;
- deleteNote — удаление заметки.

Демонстрационные записи больше не используются
как начальный список.

После создания, редактирования и удаления данные
обновляются из Supabase. Заметки сохраняются
после перезагрузки страницы и повторного входа.

### Безопасность

Создана миграция:
supabase/migrations/202611162319_notes_owner_policies.sql

Для таблицы notes настроены четыре политики RLS:
- SELECT — чтение своих заметок;
- INSERT — создание заметок от своего имени;
- UPDATE — изменение своих заметок;
- DELETE — удаление своих заметок.

Проверка владельца выполняется по условию:
auth.uid() = owner_id.

Анонимный доступ к таблице notes запрещён.
Публичный справочник categories доступен для чтения.

### Проверка

Проверены два отдельных аккаунта.
Пользователь B не получает записи пользователя A.

Попытка создать запись с чужим owner_id
отклоняется PostgreSQL с ошибкой 42501.

Проверены создание, изменение, удаление,
повторный вход и сохранение записей.
